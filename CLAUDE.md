# Cue Graphics Engine — CLAUDE.md

Unified single-process Electron app. Replaces EasyWorship/ProPresenter (worship lyric presentation) and UNO (broadcast overlay graphics). Both use cases run simultaneously — no separate modes.

**Full technical reference**: `plan/cue-master-reference.md` — read that for deep dives. This file is guard rails only: rules an agent must know before writing a single line.

---

## Hard Rules — Never Break

### Security
- `nodeIntegration: false` always. All Node/SQLite access goes through IPC via `window.cue` (contextBridge preload). Never bypass.
- Network control server (`src/main/remote/`): bind `127.0.0.1` by default (LAN is an explicit opt-in), every `/api/*` request is token-gated, and it only calls manager/IPC functions — never expose Node or the DB over it. The view-only **Remote Output** surface (`/output*`) is gated by a SEPARATE `remote_view_token` (not the control token) so a handed-out view link can never drive the service — keep the two tokens distinct.
- **`cue-media://` / `cue-thumb://` (`main/index.js`) AND the http twin `serveLocalFile` (`remote/media-serve.js`, the `/output/media` endpoint) must keep the `isUnderUserData()` containment check** — they serve raw filesystem paths, so without it a crafted URL/path is an arbitrary-file-read. Don't drop it when editing either handler.
- **The packaged CSP (`main/index.js`, `app.isPackaged` + `onHeadersReceived`) is dev-invisible** — it only applies in a build. A renderer feature that fetches a NEW remote origin (model host, API, font) works in `npm start` but is silently blocked in the packaged app until you widen the matching CSP directive. Keep `build.modulePreload.polyfill = false` (vite.renderer.config.js) so `script-src 'self'` holds.

### Media URLs
- **Never use `file://` for media.** Always `cue-media://localhost/path`. Three-slash form (`cue-media:///…`) silently fails — Chromium strips the first segment as hostname.
- **Serve `cue-media://` ranges by streaming** (`fs.createReadStream` → `Readable.toWeb`), never by reading the file/chunk into a `Buffer`. A `<video>` opens with `bytes=0-` (the whole remaining file): buffering it freezes main + spikes memory on multi-GB clips, and a fixed-size chunk cap starves the player of the multi-MB `moov` index so an hour-long video only loops its first few seconds.
- Renderer: use `src/renderer/utils/mediaUrl.js`. Output templates: inline `pathToUrl()` helper.
- `media_assets.path` is stored **absolute**. Any feature that relocates `userData` (backup/restore, data-folder move, sync) must rewrite each path to the local media dir, or assets silently fail to resolve on the new machine.
- Adding a new place that references a media asset (FK column, `settings` key, or an id embedded in a JSON column like `presentation_*.elements_json`)? Also add it to `media.findUnused()` — anything it misses gets reported as unused and is deleted by the Media cleanup tool.
- **Grid/list thumbnails use `thumbUrl()` / `<MediaThumb>` (`cue-thumb://`), never full-res `mediaUrl()`** — `cue-thumb` serves a small OS-generated JPEG cached in `userData/thumbnails`. It's a regenerable derived cache: NOT a media reference (skip `findUnused`), excluded from backups, cleared on asset delete/wipe. Keep `mediaUrl()` only for live output, full-size previews, and playing video.

### Output & NDI
- **Never `capturePage()` on NDI windows** — 4s+ latency. NDI uses the `paint` event + `setInterval(invalidate, frameMs)`.
- **Do not reintroduce a per-frame operator capture loop.** The live monitor renders from the payload, not screen capture.
- **Do not recreate a channel window for a lower-third content-mode switch** — send `content:mode` IPC to the existing window; recreating drops the NDI sender.
- **Countdown/clock graphics tick in the output template, not the operator.** Main resolves an absolute anchor (`endsAt`/`startAt`) once; `graphics-overlay.js` recomputes the digits from `Date.now()`. Never stream per-second time updates over the overlay bus. The countdown overlay slot ALSO retains its authoring spec (`source`/`targetClock`/`durationSec`) alongside the resolved anchor — `applyScene` needs it to re-resolve a FRESH anchor on Scene recall (a stored absolute anchor would be stale). Don't drop those fields as unused.
- **macOS Sequoia ignores `fullscreen:true` in the BrowserWindow constructor when `alwaysOnTop` is also set** — call `win.setFullScreen(true)` explicitly in `did-finish-load` AND re-assert it in the `leave-full-screen` event, or output windows open as floating panels on Sequoia.
- Display matching: always `display_bounds` JSON, never `display_index`.
- **A song with an all-default style saves `style_json = null`** (centre align is the default). Output/monitor `applyStyle` must treat null as `{}` and default `text-align` to **centre** — never early-return on null, or default-styled lower-third lyrics render left. Applies to `lowerthird.js`, `graphics-overlay.js`, `PreviewLivePanel`.
- **Slide transitions live in the output template (`transitions.js`), gated by main.** Two rules an "improvement" must not break: (1) a fade/zoom **keeps the new background fully opaque and fades/scales only the foreground (`#content`) in** — fading the whole stage dips the background to black on every same-bg advance; (2) **any video on either side hard-cuts** (`{type:'none'}`) — two live decoders + the single-element transport clock (§6) can't cross-fade. The op live monitor renders from payload and never animates. Don't move transitions into the operator or a capture loop.
- **Remote Output (`remote/output-page.js`) mirrors the live PROGRAM to a browser by re-rendering the screen-kind buses with the UNMODIFIED output templates** — don't fork their logic into the shim. It hosts them in a fixed 1920×1080 `#cue-frame` CSS-`zoom`ed uniform-fit + centred (letterbox) so any-aspect device matches the auditorium screen pixel-for-pixel: keep `zoom` not `transform: scale` (re-rasterises crisp), keep `#slide-elements{transform:none!important}` to neutralise `fullscreen.js`'s `scaleSlideCanvas`, and re-home `#cue-gfx` into the frame. The page string is a backtick template literal — no stray backticks in its HTML/CSS/JS or the main build silently fails to produce `.vite/build/index.js`.

### NDI input (live video sources)
- **NEVER destroy a receiver/framesync while a `fsync.video()` pull is awaiting in the native layer** — the pending promise resolves against freed memory and SIGSEGVs the whole app (silently, exit 0 under forge). `ndi-input.js` `stopReceiver` defers destruction to the pump's `finally` (`e.onIdle`) when `e.pulling`; keep that, and keep destroy order framesync-before-receiver.
- **Receive as `RGBX_RGBA` (colorFormat 2)** so output windows paint frames straight into canvas `ImageData` — no per-frame swizzle. (nativeImage thumbnails DO need the R↔B swizzle: `createFromBitmap` expects BGRA.)
- **Filter Cue's own senders (`/\(Cue - /`) out of `listSources()`** or an operator can route an output back into the program (infinite mirror).
- Live-input frames are fanned out ONLY to fullscreen-template windows + the stream window (`getLiveInputTargets`) — an ~8MB IPC copy per window per frame; never send to stage/lower-third windows that ignore them. Operator monitors render the ~2fps JPEG thumbnails pushed by main (`liveinput:preview`), never a capture loop and never the full frame bus.
- The receiver runs ONLY while a live-input payload is on program in content mode (`syncLiveInput`) — clear/logo/idle/outputs-off release it (and the camera's tally). A `live-input` cue stores `{sourceName, name}` JSON in `service_items.content` (no media_assets row, nothing for `findUnused`).
- **Live-input AUDIO is pulled in main** (`pumpAudio`, framesync `fsync.audio()` at a steady 100ms/48k cadence, normalised to planar Float32) and routed by `manager.routeLiveInputAudio`: the ONE audible screen window plays it (Web Audio → `MediaStreamDestination` → hidden `<audio>` registered via `CueMediaPlayer.attachAuxAudio` so the in-room device picker applies), NDI-out senders get it DIRECTLY from main (`ndi.sendAudio` — the element tap has nothing to capture during a live input), and the stream mixer takes it via `CueStreamFeed.pushLivePcm` in `mixed` mode only. **Keep the feed-health gate**: skip pulls while `!e.connected` or `audioQueueDepth() <= 0` — without it a vanished sender makes the framesync emit garbage/repeated-tail audio (an audible high-pitched buzz mid-service).
- **`live_inputs_enabled` (settings) is the mid-service kill switch** — `manager.setLiveInputsEnabled(false)` drops an on-air feed to 'cleared' (never a frozen last frame), releases receivers/previews, and gates `syncLiveInput` + discovery + previews + the operator's `buildPayload`. Toggled live from the Library Live tab; no restart. Don't bypass it in new live-input codepaths.

### Program audio (NDI audio + RTMP streaming)
- **In-room and stream audio are SEPARATE taps — do not re-merge them.** The in-room tap (`audio-tap.js` → `ingestAudioPcm`) feeds **NDI only**; the stream has its OWN tap inside the stream window (`stream-feed.js` → `ingestStreamAudioPcm`): the external audio-interface input + (in `mixed` mode) Cue's media. Rules both taps must keep: (1) tap via `el.captureStream()`, **never** `createMediaElementSource()` — the latter re-routes output and breaks the in-room `setSinkId` picker; (2) the foreground element keeps `crossOrigin='anonymous'` AND `cue-media://` keeps its `Access-Control-Allow-Origin` header, or the tap taints/goes silent; (3) offscreen NDI/stream windows stay **locally muted** (`mute:'1'`) — their audio IS the tap, so an unmuted offscreen window leaks to the default device. (The in-room NDI tap still needs an audible screen output as its source.)
- **Load the PCM-tap AudioWorklet from a `blob:` URL built from main-read source** (`audio:worklet-source`), NOT `addModule('pcm-tap-worklet.js')` — AudioWorklet can't reliably fetch a module from inside `app.asar`, so a relative path works in `npm start` but the tap silently dies in a packaged build (`src/output` isn't unpacked).
- **Stream Studio is its OWN program** (external feed base + Cue program + stream-targeted graphics + PiP), NOT a mirror of the in-room program. Stream-key RTMP via bundled ffmpeg (reuse `youtube/bin.js`, no OAuth); the offscreen compositor window is kept OUTSIDE the `windows` map. Non-obvious rules an "improvement" must not break: (1) **feed ffmpeg from a steady timer that re-sends the cached last frame every tick**, NOT raw `paint` events — the offscreen compositor coalesces paints on near-static scenes, so paint-driven feed starves YouTube ("not receiving enough video" → buffering); (2) scale Cue-content layers with CSS **`zoom`, never `transform: scale`** — transform caches the layer at 1920×1080 and GPU-upscales it (blurry 4K); `zoom` re-rasterizes natively (the camera feed is left native, not design-scaled); (3) the offscreen stream window needs **`backgroundThrottling:false`** or Chromium throttles the hidden window's `<video>`/timers and the feed freezes; (4) ffmpeg spawns only at **Go Live**, but the window also runs for preview (ref-counted to the Stream tab).
- **Stream layout is a free-form two-layer box model** (`{feed,program,front,lyricsOverFeed}`, % of frame), edited in `StreamLayoutEditor.jsx` and saved as `stream_presets`. Two rules an "improvement" must not break: (1) box the program (`#stage`) with a **transform that translates in element-relative `%`, NEVER `vw/vh`** — `#stage` carries a `zoom`, and `zoom` multiplies viewport-unit translates, so `vw/vh` mis-places the box (program floats off its box); (2) `programFit()` (uniform-fit-centre letterbox math) is **duplicated verbatim** in `stream-feed.js` (output) and `StreamLayoutEditor.jsx` (renderer can't import an output script) — keep them identical or the editor stops being WYSIWYG. `setStudio({layout})` REPLACES the whole layout (don't deep-merge a partial — it orphans stale boxes).
- **External video/audio input is `getUserMedia` inside the offscreen stream window.** macOS needs `NSCameraUsageDescription` (forge `extendInfo`) AND `systemPreferences.askForMediaAccess` from **main** — an offscreen window can't surface the TCC prompt. Resolve the chosen capture device **by LABEL, not deviceId** (ids salt per-origin between the operator renderer and the `file://` stream window).
- **Don't eagerly `getUserMedia` to unlock device labels** — opening a stream reconfigures the OS audio engine and audibly cuts program/stream audio. Unlock lazily, once, on first interaction with the picker (`OutputChannels.jsx`, `StreamView.jsx`).
- **`capturePage()` stutters live playback** (full GPU readback contends with the program window). Multiview keeps screen-tile capture to ~1fps with an in-flight guard — don't raise the cadence or drop the guard. (NDI tiles use the cached paint frame; never `capturePage()` an NDI window.)

### YouTube (ephemeral video)
- A YouTube cue is single-use: `service_items.item_type = 'youtube'` with the URL in `content` (**never** a `media_assets` row). The downloaded file lives in `userData/yt-cache`, wiped on quit AND startup; the cues themselves are purged on startup (`purgeYoutubeItems`). Never insert a YouTube download into `media_assets`, backups, or `media.findUnused()` — and never persist it across sessions.
- `yt-dlp` output MUST pass `-movflags +faststart` (moov atom at front) or a long clip black-screens on go-live while the player fetches the tail index.
- `yt-dlp` + `ffmpeg` are **NOT bundled** — `src/main/youtube/bin.js` auto-downloads them into `userData/bin` on first use (resolution order: `userData/bin` → system PATH → a dev-only `resources/bin/<platform>-<arch>` copy that ships in no build) and refreshes `yt-dlp` when an extraction fails. Do NOT re-add them to `extraResource`/the installer (bloat + stale yt-dlp).
- **A "Sign in to confirm you're not a bot" / "Please sign in" wall is usually a STALE yt-dlp, not a real block.** The anti-bot cascade (`withClientCascade`, §6) refreshes yt-dlp on a **bot-wall** too (not only classic extractor errors) and retries the same client tier before escalating (default → `web_embedded` → opt-in `--cookies-from-browser`). Don't narrow the refresh trigger back to extractor-only, and don't treat `private`/`members-only` as fatal — they're auth-gated and the cookies tier can unlock them.
- **Do NOT re-add "play while downloading" / live-streaming for YouTube.** It was built and removed: YouTube throttles a single sequential stream to ~playback rate, so a live ffmpeg remux can't build a buffer lead (it's the worst case for the throttle, while `--concurrent-fragments` is what makes the normal download fast). Download-first + speculative pre-fetch on paste is the design.

### Shortcuts
- **Do not use `globalShortcut`** — captures at OS level, breaks typing. Shortcuts are `keydown` on `document`, suppressed when an `INPUT`/`TEXTAREA`/`contenteditable` has focus.
- **Don't hijack the OS clipboard accelerators in the operator keydown handler.** The default shortcut modifier IS the clipboard modifier (⌘ on macOS, Ctrl elsewhere) and Clear defaults to `c`, so `OperatorView` must let ⌘C/⌘X (copy/cut) through when there's a text selection — `return` before `preventDefault`, keyed on the real clipboard modifier (`isMac ? metaKey : ctrlKey`). Otherwise ⌘C-for-Clear swallows every copy app-wide. ⌘A is repurposed to **select all rundown items**, but MUST still defer to native select-all when text is selected (`window.getSelection()` non-empty) and stays behind the input-focus guard. Don't "simplify" these guards away.

### Dependencies
- **Keep `pdfjs-dist` on v4** (PowerPoint import rasteriser). v5/v6 call native `Promise.try`, which Electron 30's Chromium (~124) lacks — the worker throws and the import hangs forever. Load the worker via Vite `?worker` + `GlobalWorkerOptions.workerPort`, never a `?url` `workerSrc` (silent main-thread fake worker = unusably slow). pdfjs stays renderer-only (needs a DOM canvas); the PPTX→PDF step is `soffice` in main.

### Scripture detection (ASR)
- **Whisper inference in main MUST disable onnxruntime's CPU memory arena** (`session_options.enableCpuMemArena:false`, also `enableMemPattern:false`). Whisper's decoder makes one large *aligned* arena allocation that Electron's PartitionAlloc shim aborts → `EXC_BREAKPOINT`/SIGTRAP that kills the whole app on the first transcription. Invisible in plain Node (no shim) and to embeddings (small allocs). DO NOT remove it as "cleanup". (`whisper-bin.js`)
- **English-only Whisper models (`*.en`) reject `language`/`task`** — passing them throws. Only pass `chunk_length_s`/`prompt_ids`.
- Detection ASR is **VAD-segmented utterances**, not a rolling window. The banned mode is specifically a **fixed window re-decoded every tick *including silence*** (the old LocalAgreement scheme — Whisper hallucinates over the silence and the lossy commit drops correct text). What IS allowed and now shipped: **VAD-gated INTERIM decodes** — while the VAD says speech is *active*, decode the accumulated **speech-only** buffer at a coarse cadence (and on a soft intra-phrase pause), latest-wins, optionally on a fast second model (tiny.en). Interims only stage a **Preview**, never auto-air; the end-of-utterance commit is unchanged and remains the source of truth. The distinction: interim-during-speech (never over silence) = OK; fixed-window-over-silence = banned. Do not "clean up" the interim path (`asr.js` `onInterim`/`runInterim`) as a rolling window. See master reference §17.
- **Two-tier ASR pipes** (`whisper-bin.js`): a `Map` of resident pipelines lets a fast interim model (tiny.en) stay loaded alongside the commit model. transcribe() **serializes per model** (onnxruntime CPU sessions aren't re-entrant) — keep that lock; concurrent decodes on one pipe corrupt output. Two more things keep the interim model from starving the authoritative commit and MUST stay: (1) **per-session CPU thread caps** (`intraOpNumThreads` from `commitThreads()`/`interimThreads()`, `interOpNumThreads:1`) — ORT's default pools are ~core-count *per session* (encoder+decoder × two models ≈ 4 pools) and oversubscribe the cores (a real speed regression); (2) **the commit preempts interims for ALL models** (`asr.js runInterim` defers any interim while a commit is decoding/queued). Interim references **suggest by default and only auto-Preview once the parse is COMPLETE (has a verse, `vStart`), clears the preview band, AND repeats on the next interim** (stable, not a one-frame mis-hear) — they never auto-air; the commit drives Live and confirms the preview in place via `candidateId`. Don't "simplify" these guards away. Content matching is **lexical-first** (`lexical-index.js`, an in-memory inverted verse index — regenerable, never persisted) with MiniLM only as the paraphrase fallback; the lexical path runs on interims with no embedding index, so don't gate content detection on `contentMatch.isBuilt`.

### In-app updater (`src/main/update/updater.js`)
- **Query `/releases` and take `[0]`, never `/releases/latest`.** CI publishes *prereleases* and `/latest` skips them, so `/latest` makes the check silently always report "up to date".
- **Pick the asset by file extension** (`.dmg` / `Setup.exe`), never a name template — real names are `Cue.dmg` / `Cue-<ver>.Setup.exe`. After download, **strip `com.apple.quarantine`** — a quarantine xattr on the ad-hoc-signed app is a Gatekeeper hard-block. No auth/token/`gh`: the repo is public. See master reference §7 *In-app updater*.
- **`settings.update_skipped_version` gates ONLY the launch-time auto-check modal, never the manual Settings "Check for Updates" button** — that button must always query fresh. Don't wire the skip into `checkForUpdate()` itself or a user who skipped v31 can never manually update to v31 later.
- **On Windows, run the downloaded NSIS Setup SILENTLY** (`spawn(setup, ['/S'])`), never `shell.openPath` — a bare open pops the full multi-page wizard on *every* auto-update. Silent mode reuses the install dir (per-user `InstallDirRegKey`) and `cue.nsi` self-relaunches (its `-Relaunch` section) since the Finish-page "Launch" checkbox is skipped. macOS stays `shell.openPath(dmg)` (mounts for drag-install). Both paths quit Cue ~1.2 s later so the installer can replace the running app.

## UI Design Guard Rails

**NEVER use AI purple / indigo** (#6366F1, #4F6EF7, #818CF8, #A5B4FC or any violet/purple). No `text-indigo-*`, `bg-indigo-*`, or `bg-slate-*`. No warm amber/brown. No box shadows on flat dark surfaces. No `rounded` above `rounded-xl` in panels.

Design language: dark, precise, mission-control broadcast engineering. Colour tokens are in `tailwind.config.js`.

Semantic colours:
- **Blue (`primary`)** = preview / staged / selected
- **Red (`secondary`)** = live / on-air
- **Green (`tertiary`)** = GO / success / active output
- **Error** = destructive actions

Typography: **Inter everywhere** — body, headlines, AND labels/chips/badges/buttons/timecodes (the `mono`/`label-sm`/`timecode-lg` tokens all map to Inter; use the `tabular-nums` utility where digits must align). Inter is bundled (`src/fonts/fonts.css`, loaded in the operator + every output window) so it always resolves; keep a sans fallback. Do NOT reintroduce JetBrains Mono or any monospace face for UI chrome. **Oswald is output templates only**, never the operator UI.

**Toolbars/headers must stay responsive — controls must never render off-screen on a small/laptop window.** The app shell is `overflow-hidden`, so a fixed, non-shrinking button row gets *clipped* (silently unreachable), not scrolled. A dense button row uses `components/ResponsiveToolbar.jsx` (descriptor-driven priority-plus: drops labels to icon-only, then collapses trailing non-`pinned` items into a "⋯" `AnchoredMenu`). A simpler title-plus-actions header instead gives the flexible middle `min-w-0 truncate` and marks action clusters `shrink-0` — the label shrinks, the buttons keep their space, never the reverse. Do not add a fixed-width, non-collapsing horizontal control row.

## Architecture Invariants

- Three processes: Main (Node/SQLite/IPC), Renderer (React + `window.cue.*` only), Output windows (plain DOM, no React).
- Output windows receive slides via `webContents.send('slide:update', payload)`.
- Media transport is a single main-process clock `{active, startAt, pausedAt, loop, muted, rate}`; position = `((pausedAt ?? now) - startAt)/1000 * rate`. Every player (`media-player.js`, preview `SyncedVideo`, `transportPosition`) multiplies by `rate`; `mediaSetRate` rebases `startAt` so position stays continuous across a speed change. Do NOT add per-window `currentTime` reporting. Do NOT use dual-element loop swap — use native `loop` attribute.
- Program audio comes from ONE screen window only (`isPrimaryAudioMonitor`). Stage and operator preview are always silent.
- Broadcast-graphics overlay is an independent bus — never coupled to the program slide bus. Each slot (`nameTitle`/`ticker`/`custom`/`countdown`) holds **one occupant per destination kind** (`{screen, ndi, stream}`) so a different graphic can run In-Room vs Online vs Stream; a fire's `target` may be `'all'`, one kind, or **an array of kinds** (any combination); each window gets `overlayForKind(kind)`. The operator UI must match "what's live" by the graphic's **`id`** carried in the slot, never by text content (two graphics sharing a body would both light up).
- **Background resolution is ONE flat cascade: `lock → per-slot override → song's own default_background_id → LIVE global default → black`** (`OperatorView.resolveBackground`, mirrored by `output/manager.js`; §9). Songs read the global default **live**, exactly like scripture/slides — do NOT snapshot it into a song's `default_background_id` at create/import time (that snapshot WAS the bug: global changes never reached existing songs). A locked song (`songs.background_locked`) pins its own bg above override+global; `setItemBackground`, `applyBackgroundToRundown` and `applyBackgroundToAll` all skip locked songs. The rundown row thumbnail resolves through the same `resolveBackground` (passed down as `resolveItemBg`) so preview matches output. When a Media-tab "Set as Global … Background" runs, refresh OperatorView's live defaults (`onBackgroundDefaultChanged`) or the change won't show until a reload.
- **Themes are ASSIGNED and resolved LIVE, never baked (v34).** The effective theme cascades item (`service_items.theme_override_id`) → rundown (`services.theme_id`) → per-kind app default (`settings.default_theme_id_{song|scripture|slide}`) → app default (`default_theme_id`) → built-in, in `OperatorView.effectiveTheme` (source of truth) mirrored best-effort by `output/manager.js`. A theme's background is layer 4 of `resolveBackground`, below the overrides and above the LEGACY `global_bg_*` fallback (§9). Do NOT re-introduce baking the theme into `song_sections.style_json` — that stale-copy WAS the original bug. `utils/themeStyle.js mergeSlideStyle` is the shared merge (a baked BASE style wins; an inline-only/null section inherits the live theme with its runs on top); `resetSongToTheme` strips a bake so a song rejoins the cascade. Font downloads run in MAIN (`db/fonts.js`), CSP-exempt — do not move them to the renderer (packaged `font-src` would block them).
- **The theme TREATMENT builders and the LT role-override resolver are mirrored VERBATIM into the output templates** (same rule as `DEFAULT_STAGE_LAYOUT`/`programFit` — a plain-DOM output script can't import from the renderer): `treatmentLayers`/`scrimBackground`/`glassBoxStyle` (`components/TreatmentOverlays.jsx` → `output/fullscreen.js`) and `resolveLtStyle`+`LT_OVERRIDE_KEYS` (`components/SongEditor.jsx` → `output/lowerthird.js`). Keep each pair identical or preview stops matching output. `#scrim` (now the treatment container) deliberately carries **no z-index** — an explicit z-index forms a stacking context that stops the tint's `mix-blend-mode` from blending with `#background`; don't "tidy" one back in.
- `window.cue.on()` returns an unsubscribe fn. Always call it in `useEffect` cleanup.
- The network remote is a virtual operator: nav commands (GO/NEXT/PREV/SELECT) are forwarded to the renderer as `remote:command` and run the SAME handlers as the keyboard. Do NOT resolve slide payloads in the main process — rundown/preview/live state lives in `OperatorView`.
- **`DEFAULT_ELEMENTS` in `stage.js` is mirrored verbatim as `DEFAULT_STAGE_LAYOUT` in `manager.js`** — keep them identical. `stage.js` is a plain `<script>` that runs inside the ASAR and cannot `import` from main; DRY-ing them breaks the packaged app. The window shows `DEFAULT_ELEMENTS` before `stage:layout` arrives, so if they diverge the initial render differs from what main thinks is the default.
- **A song section splits into variable-size slides via an inline `⁂` (U+2042) marker in `song_sections.content`** — no schema column. Keep it **symbol-only** so it stays invisible to `songs_fts` (unicode61) and the lyric matchers (`_norm`, paste-list, song detection). Expand sections to slides ONLY via `expandSongSections`/`splitSectionContent` (`utils/sectionLabels.js`) — never re-split content elsewhere — and strip/skip the marker in any new consumer of section content (e.g. `deriveStyleJson` skips it during run alignment so styling stays aligned past the break).
- **A song arrangement (`songs.arrangement_json`) is 0-based section POSITIONS, never section ids** — `songs.update()` deletes + re-inserts `song_sections` on every save, so ids churn; the editor serializes arrangement and sections in the same save (in-session it tracks `_key`s, converting at the edges). Labels always derive from the NATURAL section list (`expandSongSections`), so an arrangement-repeated chorus stays "Chorus", never "Chorus 2". Null/stale-index arrangements fall back to natural order — a song must never expand to zero slides.
- **CCLI usage logging is automatic and SNAPSHOTTED**: `song_usage` rows copy title/author/copyright at air time and `song_id` has no FK — the report must survive later song edits/deletes. Logging fires from OperatorView on live-song change; the ~12h dedupe lives in `db/songs.js logUsage` — don't also log from GO variants (slide jumps would double-count).

## Dev Commands

- `npm start` — dev server
- `npm run make` — distributable · `npm run package` — bundle only (fast packaging check)
- After any Electron version bump: `npm run rebuild` (recompiles `better-sqlite3` and `grandi`)
- **Packaging copies what Vite doesn't bundle.** The Forge Vite plugin packages only `.vite/`; the `packageAfterPrune` hook in `forge.config.js` copies the native externals' full dependency closure (`better-sqlite3`, `grandi`/`@grandi`, `tar`) into the packaged `node_modules` and copies the plain-DOM `src/output` + `src/fonts` into the asar (`asar.unpack: '**/node_modules/**'` keeps native `.node` + sibling libs like grandi's `libndi.*` on the real filesystem). These exist in `npm start` but are absent from a build, so omissions break **only in packaged apps**. Add a runtime dep Vite externalizes, or a new output-window/font file? Update that hook and verify with `npm run package`. The hook ALSO includes `onnxruntime-node` + `@huggingface/transformers` in the closure and **prunes `onnxruntime-node/bin/napi-v6/` to the build's platform/arch** — the copy pulls all five targets (~210 MB) but the loader only needs one; keep the prune or the installer re-bloats by ~150 MB with binaries that never run. **The Windows installer is an NSIS wizard** (`installer/cue.nsi`) built by the `postMake` hook, not Squirrel. Distribution/signing notes: `plan/deployment-handoff.md`.
- DB: `~/Library/Application Support/Cue/cue.db` (macOS) · `%APPDATA%\Cue\cue.db` (Windows) · schema v31
- **`autoSnapshot()` (`db/backup.js`) runs on every quit and is DB-only by design** — a synchronous `cue.db` copy into `userData/backups/` (keeps newest 5). Do NOT make it include `media/`: a tar of a multi-GB library would hang `will-quit`. The full media-inclusive bundle is the manual `.cuebackup` only.
- Version (Settings footer): `vMAJOR.MINOR.PATCH (Build N)`, all injected at build time from `vite.renderer.config.js`. **MAJOR is auto-derived** from the highest `vN` migration in `schema.js` (do not hardcode it) and **Build N** from the git commit count. Only `VERSION_MINOR`/`VERSION_PATCH` are manual: bump MINOR for features with no migration, PATCH for fixes/docs/chores, and **reset both to 0 in the same commit as a new migration** (MAJOR moves on its own).
- **One version number, everywhere — never let it drift.** The same `MAJOR.MINOR.PATCH` is the Settings footer, the `package.json` `"version"` (drives installer filenames + `.app`/`.exe` metadata), and the **release tag** (`v<that version>`, e.g. `v19.2.3`). When you bump `VERSION_MINOR`/`VERSION_PATCH`, set `package.json` `"version"` to the identical computed `MAJOR.MINOR.PATCH` **in the same commit**. A `prePackage` guard in `forge.config.js` fails the build if they diverge — it is the enforcement, do not weaken or bypass it. `package.json` is a manual mirror because it can't hold the schema-derived MAJOR or git Build N statically.
- **Cutting a release** (always the full version, never a placeholder scheme): bump the version (both places), commit to `main`, then `git tag -a v<version> -m "Cue v<version>" && git push origin v<version>` — the `v*` push triggers `.github/workflows/build-installers.yml`, which builds the dmg/exe and publishes a prerelease GitHub Release named for the tag. Pull clean (no quarantine/MOTW) with `gh release download v<version> -R will-eze/Cue -D installers`. Keep one release per version: delete superseded releases+tags with `gh release delete <tag> --cleanup-tag`. **Always launch the packaged app once per OS before distributing** — ABI/packaging breaks are invisible in `npm start` and a dev `npm run package` (the project root's `better-sqlite3` is already Electron-ABI on a dev box but Node-ABI on a clean CI checkout; the `prePackage` rebuild hook fixes it). Full distribution/signing notes: `plan/deployment-handoff.md`.
